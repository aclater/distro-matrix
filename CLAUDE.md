# CLAUDE.md: distro-matrix

Instructions for coding agents working in this repository. Read
[README.md](README.md) first.

## What this repo is

A local test harness for host-level scanners (mainly
[pqc-readiness](https://github.com/aclater/pqc-readiness)). It boots a fresh
VM per distro from an upstream cloud image, injects a NoCloud cloud-init seed
that creates a `matrix` user with an SSH key, runs the scanner as root, pulls
its output back and writes `results/<UTC ts>/report.md` and `summary.json`.

- `scripts/run-matrix.sh`: one-shot runner (boot, scan, destroy).
- `scripts/spawn-fleet/`: keep-alive fleets with an Ansible inventory;
  `scripts/teardown-fleet.sh` removes them.
- `scripts/fips-divergence.sh`: boots a FIPS fleet, scans it and runs
  `scripts/check-fips-divergence.py`, the FIPS algorithm-fence assertion.
- `distros.tsv`: the matrix. Generated by `tools/gen-distros-tsv.py`; don't
  edit it by hand.

`scripts/lib/vm.sh` holds the shared VM lifecycle: run-ID names
(`dm-<run>-<alias>`), cleanup traps, image lookup (local cache by alias, then
`--image-root`) and two backends. `--backend qemu` (the default when `vm-run`
is on PATH) launches each VM through `vm-run` with user-mode networking;
`--backend libvirt` uses `virt-install` on `qemu:///system`. `run-matrix.sh`
can also prepare guests before the scan (`--prepare`, e.g. Python 3.11 on
EL8 and Leap 15.6), validate results against a schema (`--schema`), diff two
scanner builds on the same VM (`--compare-scanner`) and capture ground-truth
command output (`--ground-truth`). `spawn-fleet.sh` takes the same
`--backend`. Each distro's serial console is saved as `<alias>/console.log`
(qemu backend): read it first when a VM never comes up on SSH.

## Rules that matter here

- **Respect the host's VM budget.** Unthrottled parallel VMs crashed the
  maintainer's laptop on 2026-10-14. `~/.local/bin/vm-run` admits VMs against
  a vCPU budget (12 while the `crc` VM runs, 18 otherwise). Use the qemu
  backend (run-matrix and spawn-fleet) with `--parallel auto`, which follows
  that budget. libvirt VMs bypass it: with `--backend libvirt`, keep to 1-2
  VMs of 1-2 vCPUs and check `vm-run --status` and `virsh list` first.
- **Never destroy a VM you didn't create.** Other runs (or OpenShift Local,
  VM `crc`) may share the hypervisor. Clean up your own VMs and work dirs,
  even on failure.
- **Images.** Cached cloud images live in `~/.cache/pqc-vm-matrix/images/
  <alias>.qcow2` (manifest: `~/.cache/pqc-vm-matrix/manifest.tsv`); the
  shared store is `/mnt/media/iso/linux/<distro-dir>/<dated filename>` (NFS
  from saturn, only reachable at home). Verify publisher checksums before
  adding an image. RHEL images need a Red Hat login and live only on saturn.
- **Verify versions** of actions, images and packages from a primary source
  (GitHub API, registry) before using them; actions are pinned by commit SHA
  with the tag as a comment, at least two weeks old.

## Checks before every PR

```bash
pre-commit run --all-files     # includes shellcheck and detect-secrets
shellcheck -s bash -e SC1091 scripts/*.sh scripts/lib/*.sh scripts/spawn-fleet/*.sh tests/*.sh
for t in tests/*.sh; do bash "$t"; done   # offline tests (need qemu-img)
ruff check scripts/ tools/
```

A change to runner behaviour must also be exercised on real VMs: at least
one EL distro (`rocky9`) and one Debian-family distro (`ubuntu2604` or
`debian13`), with the report attached to the PR.

## Workflow

- Every task starts with a GitHub issue; claim it with a comment.
- Work on a branch in a worktree; never commit to `main`.
- Commits reference the issue (`fix(runner): … (fixes #N)`), explain why, and
  end with the `Co-Authored-By:` trailer for the model in use. Git identity:
  Adam Clater <aclater@gmail.com>.
- PRs say `Closes #N`. Merge only when every check passes.
